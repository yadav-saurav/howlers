# Free hosting (no credit card)

This runs Howlers on free plans, with nothing installed on your computer:

| Part | Service | Free plan |
|---|---|---|
| Website + API (one container) | [Render](https://render.com) web service | 512 MB RAM, sleeps after 15 min without visitors |
| PostgreSQL | [Neon](https://neon.tech) | 0.5 GB |
| Redis (rate limits, feed cache) | [Upstash](https://upstash.com) | 500K commands a month |
| Uploaded images, files, podcast audio | [Supabase](https://supabase.com) Storage | 1 GB, 50 MB per file |

None of them asks for a card. Sign up to each with **Continue with GitHub** to keep it simple.

How it fits together: `deploy/render/Dockerfile` builds one image in which nginx serves the website and forwards
`/api` and `/ws` to the Spring Boot API in the same container, just like the Docker Compose setup. `render.yaml`
tells Render how to build and configure it. `deploy/render/start.sh` fills in the secrets and the public address.

**Pick one region for all four services**, the one closest to your users (for example Singapore for India, Frankfurt
for Europe, Ohio or Virginia for the US). Far-apart regions make every page slow. `render.yaml` uses `singapore`;
change `region:` there if you pick another one.

Keep a notes file open while you go: you will copy about ten values into Render at the end. Treat the passwords and
keys as secrets: never commit them or post them anywhere.

## 1. Neon (PostgreSQL)

1. Sign up at <https://console.neon.tech>, then **Create project**: any name, Postgres 17, your region.
2. On the project dashboard click **Connect**. Switch **Connection pooling off** (the database migrations need a
   direct connection). You see a string like
   `postgresql://neondb_owner:PASSWORD@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
3. Note these three values:
   - `DATABASE_URL`: `jdbc:postgresql://` + the part after `@`, for example
     `jdbc:postgresql://ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
     (the host must **not** contain `-pooler`)
   - `DATABASE_USER`: the part between `//` and `:`, for example `neondb_owner`
   - `DATABASE_PASSWORD`: the part between `:` and `@`

You don't create any tables: Howlers creates them on its first start.

## 2. Upstash (Redis)

1. Sign up at <https://console.upstash.com>, then **Create Database** (Redis): any name, your region, the **Free** plan.
2. On the database page, under **Connect**, note:
   - `REDIS_HOST`: the endpoint, for example `apt-gecko-12345.upstash.io` (no `https://`, no port)
   - `REDIS_PASSWORD`: the password / token (click the eye icon to reveal it, then copy)

The port is 6379 and TLS is switched on in `render.yaml` already.

## 3. Supabase (file storage)

1. Sign up at <https://supabase.com/dashboard>, then **New project**: any name, your region. It asks for a database
   password; Howlers doesn't use Supabase's database, so any strong password is fine.
2. Open **Storage** → **New bucket**: name it `howlers`, leave **Public bucket off** (Howlers serves every file
   through its own permission checks).
3. Open **Storage** → **Settings** (S3 connection). Make sure **S3 connection** is enabled, then note:
   - `S3_ENDPOINT`: for example `https://abcdefghijklmnop.storage.supabase.co/storage/v1/s3`
   - `S3_REGION`: for example `ap-southeast-1`
4. On the same page, under **S3 access keys**, click **New access key**. Note:
   - `S3_ACCESS_KEY`: the access key ID
   - `S3_SECRET_KEY`: the secret access key (shown only once)

## 4. Render (the app)

1. Sign up at <https://dashboard.render.com> with GitHub and allow Render to see this repository.
2. Click **New** → **Blueprint**, pick this repository and the `main` branch. Render reads `render.yaml`.
3. Render asks for each value marked `sync: false`. Paste the ten values from steps 1 to 3:
   `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`, `REDIS_HOST`, `REDIS_PASSWORD`, `S3_ENDPOINT`, `S3_REGION`,
   `S3_ACCESS_KEY`, `S3_SECRET_KEY`. `HOWLERS_SECRET_SEED` is generated by Render; don't touch it.
4. Click **Apply** / **Deploy Blueprint**. The first build takes about 10 to 15 minutes (it compiles the frontend and
   the Java API). Follow it in the service's **Logs** tab.
5. When the logs show `Started HowlersApplication`, open the address at the top of the service page, for example
   `https://howlers-ab12.onrender.com`.

The public address, CORS origin and passkey origin are taken from Render's own URL automatically. Every push to
`main` deploys again.

### Make yourself the admin

1. On the live site, **Sign up** with your own username.
2. In Neon, open **SQL Editor** and run (with your username):
   ```sql
   UPDATE users SET role = 'ADMIN' WHERE username = 'your-username';
   ```
3. Within about 30 seconds the **Admin** area appears in the menu. From there you can make other admins.

The site starts empty (the demo seed is off in production because its accounts share a public password). Create the
first communities yourself.

## Optional features

Without any API keys every core feature works: communities, posts, comments, votes, feeds, search, messages, pack
rooms, realtime updates, moderation and admin. These need a key; add them in Render → your service →
**Environment**, then **Save, rebuild and deploy**:

| Feature | Variables | Without them |
|---|---|---|
| Community AI and the AI digest | `ANTHROPIC_API_KEY`, `AI_MODEL` (a model id from your AI provider) | Offline cited summaries |
| Podcast voices | `ELEVENLABS_API_KEY` | Podcasts without generated audio |
| Emails (verification, password reset, new-device alerts) | `MAIL_MODE=brevo`, `BREVO_API_KEY`, `MAIL_FROM_ADDRESS` (a sender verified in Brevo), `MAIL_FROM_NAME=Howlers` | Emails only appear in the Render logs, so password reset doesn't work |
| Stripe test payments for moderator funding | `FUNDING_PROVIDER=stripe`, `STRIPE_SECRET_KEY` (`sk_test_...`), `STRIPE_WEBHOOK_SECRET` (`whsec_...` from a Stripe webhook endpoint at `https://YOUR-APP.onrender.com/api/v1/funding/webhooks/stripe`) | Clearly labelled demo payments |
| Browser push notifications | `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (see docs/DEPLOYMENT.md, section 12) | In-app notifications only |

With `FUNDING_PROVIDER=stripe` the API refuses to start until `STRIPE_WEBHOOK_SECRET` is set too.

## Using your own domain

Add it in Render → your service → **Settings** → **Custom Domains** and follow the DNS instructions. Then set
`APP_PUBLIC_URL=https://your.domain` in **Environment**. Passkeys are tied to the domain, so do this before people
register passkeys.

## What to expect on the free plans

- **Sleeping**: after 15 minutes without visitors Render stops the app; the next visit waits 30 to 60 seconds while
  it starts again. Live updates reconnect by themselves. A free uptime monitor that opens `/healthz` every 10 minutes
  keeps it awake (one always-on service fits in Render's 750 free hours a month).
- **Memory**: the container has 512 MB. The Java settings in `start.sh` are tuned for that. A few dozen active users
  are fine; for more, move to a paid instance and raise `-Xmx` through `JAVA_OPTS`.
- **Storage**: Neon has 0.5 GB of data and Supabase 1 GB of files (50 MB per file, so `render.yaml` caps uploads at
  50 MB). Supabase pauses projects after a week with no activity; open its dashboard and **Restore** if uploads fail.
- **Upstash**: 500K commands a month. If the limit is reached, Howlers keeps working (rate limits fall back to
  in-memory counting and feeds are served uncached).

## Troubleshooting

Look in Render → your service → **Logs** first.

| Log message | Fix |
|---|---|
| `Refusing to start the prod profile with unsafe settings` | The listed variables are missing or too weak. `DATABASE_PASSWORD` must be at least 12 characters. If `HOWLERS_SECRET_SEED` is missing, add it with any long random value (and never change it afterwards). |
| `Connection to ... refused`, `FATAL: password authentication failed` | Recheck the three Neon values. `DATABASE_URL` must start with `jdbc:postgresql://` and end with `?sslmode=require`. |
| Flyway errors mentioning `pooler` or `prepared statement` | Use Neon's direct host (connection pooling off). |
| `Rate limiter: Redis unavailable` | Recheck `REDIS_HOST` (no `https://`, no port) and `REDIS_PASSWORD`. The site keeps working meanwhile. |
| Uploads fail with `AccessDenied` / `NoSuchBucket` | Check the bucket is named `howlers`, S3 connection is enabled in Supabase and the access key values. |
| `OutOfMemoryError` or the service restarting | Lower `-Xmx` in `JAVA_OPTS` (for example `-Xmx220m ...`, keeping the other flags from `start.sh`) or move to a larger instance. |
| Build fails | Open the build log; the frontend and backend steps are labelled. The same checks run in GitHub Actions on every push. |
